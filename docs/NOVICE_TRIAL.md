# 鉴实 新手受控试用任务与记录

状态：待实际参与者执行。2026-10-17交付；自动化验证不计为真实新手试用。依据本聊天已认可方案第14—15节，建议5位目标用户，至少4位独立完成闭环；关键授权或结论范围出现误解即需修正后复验。小样本只用于找问题。

## 组织者先准备

1. 使用独立工作台数据目录和“用工单示例体验”生成的源码副本，记录工作台地址、源码路径、日期、版本与匿名参与者编号。不得使用原项目数据库或修改既有历史。
2. 由具备技术能力的人实际核对接入、原业务预期和精确检查方法；需要审核时完成真实业务确认与技术审核。没有可用方法或审核人员，只能测试受阻路径，不能填测试姓名冒充正式审核。
3. 为发现问题练习，仅在该练习副本的src/server.ts内，将提交操作保存标题的值从请求标题改为固定的错误文本。保留查询、初始化、原规则和断言。先由组织者在隔离记录中核对确实检出标题不符，再建立参与者自己的练习记录；不预造或改写结果。
4. 修复可以由参与者使用其编码工具或请开发者完成；帮助应限于修改练习项目。测试者不口头解释鉴实页面、代操作、代确认或暗示答案。首次卡住、求助与协作分别记下。
5. 需要模型时由实际使用者在本机设置并确认发送接收方、材料与预算；不能为试用自动外发源码。已有有效检查方法可直接复用，不要求重复生成。

建议先核对[第三阶段证据与限制](evidence/novice-entry-2026-10-17.md)。本机副本不是操作系统安全沙箱，只使用当前支持范围内的受控示例。

## 给参与者的任务

> 你有一个工单网站，需要确认“提交后查到的标题与自己提交的一致”。请使用鉴实检查这件事，找到有证据的问题，准备足够的修复材料，交给开发者或你使用的编码工具修复，然后回到原结果复测。最后告诉我们这次结论覆盖什么、还有什么不能判断。请按界面自行操作；需要帮助时直接提出。

开始入口为工作台“选择项目”。展开“没有合适的项目？用示例练习”，创建并导入已安排的练习副本；若组织者已准备含缺陷的独立副本，直接选择该目录，不另外改动或沿用他人的授权。

示例可跳过AI业务分析；先在“运行检查→运行条件”接入并明确准备环境，再在“确认检查”加入“提交结果保存”，核对原预期，准备或选择有效检查方法。其余按原四阶段完成。此段可作为试用后的自助提示；若在试用中使用，应记录一次提示。

## 观察与验收

| 项目 | 要记录的事实／通过标准 |
| --- | --- |
| 首次卡住 | 页面、实际文字、当时想做什么；没有卡住写无 |
| 求助次数 | 主持人解释或提示次数；开发者修复协作单列 |
| 首个有效结论 | 开始时间、有效结果时间、耗时；未完成不补估计值 |
| 问题与材料 | 能找到原预期、实际不符及证据；预览并复制／下载真实修复材料 |
| 复测 | 找到原记录旁的入口，核对变化与新的执行授权，生成关联运行；旧记录仍可查 |
| 结论理解 | 不把未知当失败，不把本轮通过当全站正确；标准变化不说原缺陷已修复 |
| 授权理解 | 能指出哪些操作发送代码、创建副本、启动程序或执行写入；查看与导航不当成执行 |
| 边界路径 | 缺配置能找到接入材料；缺审核能停在待处理，不随便填名字；仅观察不当成已确认正确性 |

体验结束后先让参与者用自己的话解释“静态条件符合”“尚不能判断”“本轮所选检查通过”“原问题本次未复现”，再记录原话和对应页面；不要预先教答案。

## 单人记录模板

| 字段 | 实际记录 |
| --- | --- |
| 匿名编号／日期／版本／设备宽度 | 待填写 |
| 新手背景与是否熟悉HTTP／自动测试 | 待填写 |
| 工作台、练习目录、原运行、新复测 | 待填写；不记录密码或Token |
| 开始／首个有效结果／结束时间 | 待填写 |
| 首次卡住位置与原话 | 待填写 |
| 主持人提示次数／技术修复协作 | 待填写，分开计数 |
| 材料是否完整／复测是否关联／历史是否可查 | 待填写 |
| 对发送、执行、未知和通过范围的解释 | 待填写原话 |
| 独立完成／需提示／未完成及原因 | 待填写 |
| 问题、严重程度、建议调整、复验结果 | 待填写；建议不直接变成新功能范围 |

汇总时写“实际参与N人，其中M人独立完成”，附关键误解和未完成原因。没有真实记录不填写完成率；只有得到实际反馈后才实施必要的针对性调整，新的功能仍另行确认范围。
