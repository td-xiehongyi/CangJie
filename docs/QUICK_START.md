# Windows 一键启动与本地 API 设置

更新：2026-10-17；启动方式沿用main@7581aae，本轮补充四阶段入口。这里说明仓库开发工作台的当前启动方式，不是安装器或正式发行版。已有开发检查与开放验收见[证据索引](evidence/README.md)；Shell实际双击、默认浏览器和原生窗口仍需人工验收，四阶段验证范围单独记录。

## 第一次准备

1. 安装Node.js 24.x（包含npm），重新打开终端。
2. 在项目根目录执行`npm ci --ignore-scripts`，按锁文件安装依赖。首次安装通常需要网络。双击入口本身不自动下载依赖、不修改执行策略、不申请管理员权限。
3. 双击根目录`Start-CangJie.cmd`。也可在根目录执行`npm run start:oneclick`。

启动器定位自己的项目目录，因此目录包含空格或中文不需要手动改脚本。它核对Node与依赖，重新编译契约、宿主、三个样例和前端，成功后启动工作台，再请求默认浏览器打开终端显示的本机地址。编译失败则停止并显示错误，不继续启动旧dist。有仓颉 SDK 时还会重新构建核心；已有核心但缺 SDK 时明确报 CORE_REBUILD_REQUIRED 并停止，防止新宿主沿用旧核心。可用 CANGJIE_SDK / CANGJIE_STDX 指定本机工具目录。Node/依赖缺失时显示准备命令，不能把这种情况称为“首次零配置启动”。

默认地址为http://127.0.0.1:4317；以终端实际显示为准。浏览器未自动打开时手动访问该地址。端口被占用时退出并提示，不自动连接来源不明的已占用服务；先关闭已运行的工作台，或在终端设置`WORKBENCH_PORT`后启动。重复双击不承诺切换回原窗口。

运行期间保留控制台；Ctrl+C用于停止。只关闭网页标签不停止后台。启动不会自动调用模型、生成候选或执行被测项目。

若没有SDK且没有`verification-core.exe`，入口会提示能力限制，但仍可打开界面和保存API设置。候选准入、业务执行和验证包复跑需要原生仓颉核心及对应工具；本入口不代替SDK安装、核心构建或正式验收。

## 体验四阶段流程

打开工作台后，主导航为“选择项目 → 确认检查 → 运行检查 → 处理结果”。窄屏点击“查看流程”展开。已有项目从右上角切换；运行检查中的任务入口分别为运行条件、检查方法、方案审核和开始检查。选择项目、导航或刷新均不会自动发送代码、调用模型或执行检查。

需要检查时，先确认范围与业务预期，再核对运行条件与方案；所有原有授权和验证仍适用。查看旧结果可直接进入处理结果并选择历史运行。第一阶段详细体验与验证见[四阶段记录](evidence/four-stage-navigation-2026-10-17.md)。

结果按发现问题、尚不能判断、本轮通过、仅观察分组，展开卡片核对预期、实际和证据。“预览修复材料”只读取报告，核对后可复制或下载。修复或补齐条件后明确准备复测，重新确认源码／映射变化与测试环境再执行；新记录显示与原运行的逐项对比。不同标准或证据不足不会判成修复，旧记录保留。已有历史没有关联复测时不显示对比；无需为查看结果启动检查。第二阶段操作和验证见[问题—修复—复测记录](evidence/result-repair-retest-2026-10-17.md)。宿主重启后，正式执行前须重新准备临时测试凭据。

## 从示例开始练习

在“选择项目”展开“没有合适的项目？用示例练习”，点击“用工单示例体验”。它只把内置工单源码复制到本机practice-projects内的独立目录，并填入路径；随后仍须明确“导入源码”，不会自动运行或外发。每次创建保留不同副本，不修改原样例或旧历史。

导入后先看静态支持结论。缺配置可下载接入补充说明；符合静态条件仍不代表已经能运行。示例可跳过AI业务分析：先到“运行检查→运行条件”明确准备环境，再到“确认检查”加入“提交结果保存”，核对预期；方法仍需具备当前资格和必要实际审核。首次结果后按原入口准备修复材料与关联复测，仅修改练习副本。

第三阶段[证据与限制](evidence/novice-entry-2026-10-17.md)、[真实新手试用任务与记录](NOVICE_TRIAL.md)已提供；目前没有真实参与者完成率，自动测试不替代新手试用。

## 保存 API

进入“模型设置”，填写接口地址、精确模型名称和API Key：

- **保存到本机**：只调用本机设置接口，不发模型连接请求；接口地址和模型名称写入当前工作台配置，重启后恢复。
- **记住密钥**：需主动勾选；Key写入当前Windows用户的凭据管理器。本地JSON只保存不可直接用作API Key的凭据引用，不保存Key明文。下次在同一Windows用户和同一数据目录启动时按引用读取。
- **不勾选**：Key只在宿主会话内存；地址和模型仍保存，退出/重启后需重新输入Key。
- **保存并调用模型检查连接**：保存后向所填服务发起一次最小模型检查，可能产生服务商费用。不是全项目分析，也不证明业务理解效果。
- **清除密钥**：删除当前配置引用对应的凭据；不会清空Windows中的其他凭据，地址和模型仍保留。

保存失败会显示错误。Windows凭据管理器不可用时不会静默退回明文保存。Key输入成功提交后清空输入框；查看配置接口不会返回Key。不要把Key放入启动脚本、Git、截图或聊天。

本仓库存在`main-version.json`时，使用其中runtime.directory指定的目录；当前默认`.local-data/natural-workflow-preview/state.json`。无该文件的交付目录默认`.local-data/workbench/state.json`。`state.json`包含非秘密设置及项目状态，API Key仍在Windows凭据管理器或会话内存。

同一目录重启可恢复设置；切换配置目录、换Windows用户或换电脑不保证恢复Key。本功能没有云同步、Key导出或跨电脑迁移。不要为迁移复制凭据或把`.local-data`提交到仓库。

## 目录选择与模型接口

以下行为已纳入当前代码；旧分支修复过程和验证日期仍保留在证据页，不作为另一套启动流程。

- **粘贴目录**：01导入源码、04运行准备均保留路径输入框。可粘贴完整路径或 Windows“复制为路径”的带双引号文本；只去除外围空白及成对双引号，不执行路径中的命令，也不展开环境变量。
- **Windows 选择窗口**：改用系统 Common Item Dialog 的文件夹模式。在地址栏按 Ctrl+L 或 Alt+D、粘贴目录、回车，再点击“选择文件夹”。仅返回目录，不会直接导入或发送文件。取消不更改页面路径；无交互桌面或窗口失败时继续使用页面输入框。此轮尚未实测 Windows 原生窗口。
- **接口范围**：目前支持 Chat Completions JSON 请求协议，服务须支持 `response_format: json_object`、`max_tokens` 和非流式返回。填写 HTTPS 基础域名或 `/v1`，不能填完整 `/chat/completions` 路径；不支持任意协议或任意自定义路径。仍需填写服务商实际支持的模型名。
- **连接检查**：同一时刻仅允许一次；修改模型、密钥或服务后，旧请求的结果不认证新配置。只增加等价的尾部斜杠不删除密钥。不同基础路径仍视为不同配置。
- **失败处理**：参数拒绝、付费要求、限流、超时分别提示。不会透出原始供应商错误正文，不自动重试或切换模型。用户继续时仍受累计请求、时间和 token 预算限制。
- **预算**：可获得合法用量时，即使输出截断或 JSON 无效，也据此结算。供应商省略用量时，保留保守预留并标记未知，可继续接收合法正文；它不是实际收费数字。提供非法用量仍拒绝。输出必须符合业务结构及来源校验，缺少用量不放宽这些校验。

详见[修复与验证证据](evidence/model-reliability-2026-10-16.md)。
