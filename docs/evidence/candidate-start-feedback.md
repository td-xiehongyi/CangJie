# 创建方案后的确认与进度定位

日期：2026-10-14。范围：4317源码工作台前端；不重启宿主、不改模型或项目配置、不操作8098/旧ZIP。

## 原因

用户截图显示编辑规则已加入且确认。只读现场状态确认：环境准备成功、deepseek-flash已配置且有Key、发送同意尚未提供、没有候选任务。点击创建时进入发送确认分支是正确行为，但确认卡被渲染在整张规则卡之后，没有滚动、焦点或按钮附近反馈，用户看不到新增步骤。

## 修改

- 将“创建方案前准备”放在对应规则的操作区域内，展开时自动滚动并聚焦该区域。
- 发送同意仍由用户勾选，展示服务和文件范围；完成准备与确认后才提交创建请求。
- 候选请求受理后立即定位到生成/验证进度，自动验证结束后继续定位审核。轮询同一状态不会重复滚动；隐藏页面不会夺焦点。
- 只构建并更新前端静态资源。现场核对4317已返回新JS，原项目、规则选择、模型名和hasKey均保留；本任务没有替用户发送项目给真实模型。
