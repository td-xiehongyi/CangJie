# 会话恢复与业务检查体验优化（2026-10-14）

范围：用户授权修复 SESSION_REQUIRED 并落实本轮流程易用性审查。沿用 main-2026-10-14；只改前端，不变更宿主认证、业务执行或模板准入规则。

## 原因与修复

隔离工作台实际重启后，旧浏览器令牌收到401 SESSION_REQUIRED；原客户端只在首次进入取令牌，轮询及两个选择恢复按钮继续使用旧令牌。原页面直接显示内部错误码，没有有效重连入口。

- 统一识别会话失效，暂停失效会话请求，显示中文说明与“重新连接工作台”，定位提示以便用户发现。
- 重连只取新令牌、读最新状态；不重载页面、不清空组件输入，不重放创建方案、审核、发布或运行请求。
- 未保存检查选择在重连后继续保留，明确等待用户选择“保留本页并重新保存 / 加载已保存的选择”。保留本页时先读最新修订，后续并发冲突仍由宿主拒绝；确认状态仍经宿主校验。
- 审核说明和准备信息遇到会话失效后保留，重连后提示手动继续；重连失败可再次尝试。

## 界面变化

- “选择流程”改为“要检查网站的哪种操作？”。工单项目显示“新增工单 / 修改工单标题（其他字段不变）”，其他项目使用通用“记录”用语。
- 明确业务操作不是检查方案编辑；解释加入本轮与确认预期的差别。方案版本及适用条件统一使用“检查方案”。
- AI入口显示中文“AI 推荐的业务操作”，原始名称保留于详情，不伪造翻译或扩展验证范围。
- 已发布方案默认折叠生成步骤与验证证据，业务验证页只保留一个“准备本轮检查”入口。新版本仍需用户确认预期，不通过点击继续隐式确认。
- 窄屏五步导航压为一行，保留当前步骤文字与状态。
