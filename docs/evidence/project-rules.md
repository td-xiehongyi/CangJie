## 已实现边界

- 新规则保存在项目内独立版本库，不写全局公共规则目录。建议原有事实、候选预期及关键问题保持可查；所有嵌套事实、预期、风险引用合并进审计来源。风险原文可沿分析/建议引用回查，不被确认成事实。
- 必须逐题回答关键问题、独立填写正确预期并显式确认。实现“任何人可修改”与需求“仅所有者”冲突时保留两者；确认不会自动选择、生成或执行。
- 项目修订号保护多页面写入，规则版本与内容摘要保护精确引用。语义纠正追加pending新版本，清除旧选择；重新确认再追加confirmed新版本。原confirmed/pending版本均不可变、仍可查看，纠正记录追加保留。
- 新规则选中仅保存草稿。其他项目、过期版本、变更源码、变更项目目录均不得被重新确认或选择。规则写入、源码项目保存、既有项目运行配置导入使用同项目原生互斥锁；锁内完整重查项目身份、根目录和全部来源，并一直持锁至文件sync/原子替换，避免校验IO与保存之间重绑目录。
- API在原本机host会话认证与来源检查之后挂载。只从宿主已保存分析读取建议，客户端的qualified/readiness声明不能签发资格；历史读取不启动任务，旧固定规则流程保留。
- D5只读判定reusable、generatable、needs_conditions、needs_capability。检查精确project/id/version/contentHash、动作、角色、参数、映射、观察字段及完整性、断言表达式、数据条件与独立正常/缺陷/证据不足资源。HTTP200不能代替业务断言，映射/完整性声明不等于已验证业务观察，缺title等真实参数绑定列映射缺口。
- S3宿主尚无动态规则的独立资源或已合格项目模板目录，因此真实新规则诚实显示资源/能力缺口；四状态纯逻辑用明确测试输入核验，不借旧规则资源放行。结构化requirements可由受认证API保存，UI不猜测其映射。候选生成、验证资源接入、审核、目标执行属于后续阶段。
- UI提示未选/受阻范围，版本库确认与固定检查执行隔离。未保存语义或纠正说明即使收起编辑器仍是dirty；须先保存修订或显式放弃，不能用确认按钮签认未显示的旧预期。冲突保留输入，并要求重新核对后手动保存。
