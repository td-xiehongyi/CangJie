# AI开发网站验证系统：本机交付复现

普通运行交付是 Windows x64 开发预览，不代表正式发布。其他电脑兼容性未验证。
`node scripts/package.mjs --source-only`生成的目录另标source-development-delivery/coreBuilt=false，不含原生核心，源码分析可使用已构建宿主；候选准入、业务执行与复跑须先在Windows构建真实核心并续验。不要将它作为正式运行包。
使用全新目录与空白配置，不复制开发目录的 `.local-data`、测试结果、凭据或数据库。

## 环境与启动

要求 Node.js 24.x、npm 11.x、仓颉1.0.5及stdx1.0.5.1。历史Windows记录是Node24.19.0/npm11.17.0；2026-10-15云端开发复测是Linux Node24.19.0/npm11.9.0。两者是不同环境，不代表当前安装已核验。新打包器manifest.dependencies只写依赖要求，packagingEnvironment记录实际打包进程的Node版本、操作系统和架构。打包器不调用npm，npm.version为null且status为not-probed；该字段不是安装或运行环境验收。旧包中的固定verified标签仅作历史记录，不能据此宣称本次Windows验收通过。
在本目录打开 PowerShell，先 `npm ci --omit=dev --ignore-scripts` 安装锁定依赖。
首次安装需访问npm仓库；本机离线缓存不完整，不承诺离线首次安装。
仓颉可用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-tools.ps1` 下载校验安装到本目录；也可显式设置
`$env:CANGJIE_SDK` 和 `$env:CANGJIE_STDX` 为本机已安装版本目录，记录实际路径。
容量验证另运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-k6.ps1`，固定k6 2.3.0并校验摘要。
以上执行策略只作用于该次 PowerShell 进程，不修改系统设置。
执行 `npm start`，访问 http://127.0.0.1:4317 。端口占用时在启动前设置 `$env:WORKBENCH_PORT=4318`。
在终端按 Ctrl+C 退出后台；关闭浏览器标签不等于停止工具。
新增双击入口：先执行 `npm ci --ignore-scripts` 安装完整开发依赖，再双击根目录 `Start-JianShi.cmd`（或 `npm run start:oneclick`）。入口每次重新构建再启动并请求打开浏览器；仅安装omit=dev依赖时请使用前述npm start。入口不自动安装依赖或SDK。

## 样例与配置

项目接入选择本目录 `samples/ticket`，用途填写“合成工单业务检查”。
默认使用自动测试账号：确认测试环境后点击准备，工具生成两个普通测试用户，
在独立合成数据副本初始化并核对登录。密码仅保存在宿主会话内存。
如选择手动账号模式，可使用 alpha / user-a / owner 和 beta / user-b / other，
角色都是user，并为两个账号分别输入本次测试密码。
模型设置由使用者手动输入接口地址、模型名和API Key。默认仅本次使用；
勾选记住后只写Windows凭据管理器，清除按钮只删除此配置自己的引用。
“保存到本机”只保存设置，不发送模型请求；“保存并调用模型检查连接”会向配置服务发起一次检查，可能计费。地址与模型名称写入工作台本地state.json，只有Windows凭据引用可以随配置保存，Key不写JSON。保存失败不回退明文；不记住时重启需重新输入Key。
不得把密码或API Key粘贴到报告或演示材料。

## 验证与重开

普通交付包含源码索引运行所需TypeScript生产依赖、公开discovery/status-transition契约与ticket/registration/status-ticket三个样例，不含候选验证答案。新候选验证前，由开发者单独提供 `developer-resources-*` 目录，
在交付目录执行 `node scripts/package.mjs --install-resources "资源包绝对路径"`。
当前独立资源为reference-v2，包含旧规则与status-transition两套冻结私有资源；旧reference-v1仍按旧清单兼容安装，未知版本拒绝。安装前后核对文件摘要和冻结锁，遇到已有不同内容拒绝覆盖；安装不是对并发目录修改的原子事务，出现竞态将拒绝报告成功，不自动删除已写入的相同或失败文件。资源只供本机独立验收，不能发送给模型。
未安装时显示 `VALIDATION_RESOURCES_REQUIRED`（需要开发者验收资源），不得绕过资格检查。
安装前可执行 `node scripts/package.mjs --verify "交付目录绝对路径"` 核对原始交付文件。
安装依赖、资源或产生使用数据后的目录不再是原始空包，严格完整性检查会拒绝这些新增文件。

按编号流程操作：01导入源码，02选择AI读取或自行填写，03确认本轮业务与目标，04准备运行条件，05选择或生成方案。02先本机预览，再明确同意发送；候选生成的发送范围另外核对。
06—08在05内展示创建、独立验证和项目试运行；新候选准备完成后前往09保存材料并完成实际双重审核。已有有效方案核对精确版本证据后可前往10，不重复生成。
新候选会尝试预填“AI参考，待确认”的适用条件、排除条件及使用说明，核对后保存。
已保存说明可在刷新和重开后恢复，修改后重新保存和确认；审核发布后在10核对本轮条件并明确启动检查。
其它已选检查缺少方案时，先完成其余方案；旧候选缺少参考说明可手动填写。
候选验证、目标试运行和实际双审核完成前不能称为正式可复用模板。
11的“更多导出格式与备份”下载Markdown及验证包；退出后台后重新启动，同一交付目录加载该包并在12明确准备复测，
自动账号模式需重新准备测试环境；手动模式需重新输入测试密码。
检查新报告关联旧运行且旧证据保持。
修改源项目后要重新接入并确认变化，不能声称原条件重跑。
源码分析按显式业务范围保守核验；范围内新增/删除/变化，即便未被引用，也清除当前可用选择与来源确认视图。默认全根范围没有配置文件豁免；若先分析src/公开文档后补运行配置，必须事先明确这个业务范围，配置仍另受运行资格复核。根目录不可访问时旧分析/报告可看，但不能确认、继续选择或复跑。纠正记录只能追加待确认版本，不改旧报告。
v1验证包按原样读取，未知schema/interpreter版本拒绝执行；查看包不调用模型或核心。移动工具交付目录不会把旧项目规则绑定迁移到另一源码根目录。缺适配、工具、独立资源或精确资格时只能查看，不能继承旧通过状态复跑。
目标负载在03选择目标、10.2明确执行，11仅查看与导出。先核对来源运行的源码/映射/数据/身份与当前环境精确一致，并重新核验仍有效的方案；不沿用旧报告结论替代资格。每实验继续复核，停用或来源变更会阻断。所选规则均有当前有效的确认与通过结果后才准入，报告包含停止原因、在途结算、未知及限制。

## 能力边界

新增项目规则执行桥仅支持已审查的工单关闭状态语义及精确动作/字段映射。自由文本规则可以保存，不代表可以编译执行；无对应执行能力或独立资源时必须保持受阻。
分析每轮处理前、provider调用前和最终结果引用校验后重建选中范围，观测到变化即保存stale，停止后续调用；不撤回已发请求，也不提供文件系统原子快照。公开读取、确认和执行前的来源校验继续保留。为结果可复现，分析期间仍应避免修改选中源码。


支持已核对的 Node24 / Express5 / Token / HTTP JSON 模式及合成数据初始化。
缺少初始化或取证入口时保留受阻状态并交付补充说明，不自动修复网站代码。
模型断线、取消、预算耗尽会保留任务状态；重试不会清零预算。
自动化中的确定性模型和测试审核身份只证明软件流程，不证明真实AI生成或人工审核。
T10两组价值对照尚未开展；本机结果不能外推线上最大容量。

## 源码与重新构建

包中包括实际运行组件对应的仓颉、宿主、网页与合成样例源码；不含开发历史或无关源码。
需要重新构建时执行 `npm ci --ignore-scripts` 安装开发依赖，然后 `npm run check`。打包前也必须在预定发布源码上完成相应构建与检查；打包器本身复制已有dist及源码，不替代构建或证明二者同步。
