## 导航与完成条件

主路径为 **01 → 02 → 03 → 04 → 05 → 09 → 10 → 11**，12为可选修复复测。06—08显示在05内，分别表示创建/适配、独立验证和项目试运行；旧链接和保存位置仍映射到05。原13已并入11。

| 编号与界面名称 | 用户动作及本步产出 | 缺条件时 |
| --- | --- | --- |
| 01 导入项目 | 选择源码或已有项目，建立项目与源码快照 | 修正不可读路径；不要求先启动网站或提供账号 |
| 02 了解与分析业务 | 选择AI读取，或前往03自行填写 | 缺模型可人工填写；超限/来源变化按原因处理 |
| 03 确认要检查的业务 | 核对预期与问题，保存规则、检查选择和测试目标 | 空选择不能继续；AI建议和人工说明草稿都不自动取得执行资格 |
| 04 检查运行条件 | 核对同一项目目录、隔离副本、测试账号/数据与接口映射，准备环境 | 补初始化、映射、工具或凭据；同意测试环境不等于准备成功 |
| 05 选择或生成检查方案 | 选择已有精确版本或明确调用模型生成，在本页查看06—08进度和证据 | 待适配、待扩展或待澄清保留缺口；不自动缩减已选范围 |
| 09 审核并确定方案 | 保存本版材料，实际业务确认与技术审核后固定版本 | 缺证据、材料或任一审核不能发布 |
| 10 执行正式检查 | 10.1明确启动业务检查；10.2满足准入后另行执行目标负载 | 当前资格、来源、环境与凭据由宿主重新核验 |
| 11 结果、导出与保存复用 | 选择对应运行，查看结论/未覆盖范围，导出报告或验证包后可结束 | 失败、未知或部分结果如实保留，不能仅凭流程完成写业务通过 |
| 12 修复与复测 | 主动启用、核对变化，产生关联旧运行的新复测 | 原方案失效先补相应条件；未启用不阻塞11 |

点击编号只改变查看位置，不启动模型或业务执行。当前页与后台进度分开，轮询不应夺取输入或自动跳页。模型设置是可返回原任务的支线。

- 有有效方案：01 → 02选择人工路径 → 03 → 04 → 05核对历史证据及当前适配 → 10 → 11，不重复生成和审核。
- 需要新方案：01 → 02 → 03 → 04 → 05内完成06—08 → 09 → 10 → 11。
- 只了解业务：完成01—03后即可停止；未执行步骤不能记为检查通过。
- 缺执行能力：在05导出缺口并保留未覆盖；确认自由文本业务不等于平台已支持执行。

## 01与02 导入和分析

01输入本机源码目录并点击“导入源码”。目录输入支持直接粘贴及资源管理器“复制为路径”的成对双引号；“选择文件夹”仅返回目录，不直接发送文件。取消或原生窗口不可用时可继续粘贴路径。

02有两个入口：

1. **AI读取项目分析**：点击“读取项目”，仅在本机刷新索引并预览材料。核对接收方、模型和“查看完整文件清单与正文”，再点“同意发送并开始分析”。没有预览与同意不外发。
2. **自行填写业务**：点“前往03填写业务”，不调用模型。在03保存业务说明并确认本轮业务；需要运行但尚无可选基础检查时，先到04接入运行条件，再返回03选择。

当前AI界面自动使用项目内全部允许文本，包含项目自身测试，不再要求填写范围或提示词。历史会话和旧接口的范围/提示词绑定仍校验；不能把旧片段读取标成全文件分析。

允许文本包括JS/TS、JSON、MD/TXT、Python、Java、仓颉、Go、Rust、Vue/Svelte、HTML/CSS/SCSS、SQL、YAML、TOML及Shell/PowerShell。非JS/TS仅读取正文，不保证语法关系解析。密钥、数据库、依赖、构建产物、二进制、工具私有验证资源和越界链接被排除；秘密检测不保证发现所有秘密。已经发送的项目测试不能再算模型未见的留出答案。

分析上限为单文件及正文总量各65536字节（64 KiB）、包含协议开销的请求98304字节（96 KiB），累计8次请求、10分钟、120000 token。超限阻断，不静默截断、摘要或分批；当前界面可改用自行填写业务或选择更小的独立项目目录，不能假定有范围编辑按钮。预算不是货币报价或模型上下文保证。

确认绑定项目快照、文件集合、接收方、模型及分析输入，变化后重新读取并确认。输出中的源码事实、文档/测试预期和AI推断须分别核对引用、限制及未决问题，分析完成不证明穷尽业务。

分析暂停或失败时先看原因：有资格时可“继续原分析（调用模型）”；若界面明确提供“恢复已保存的业务草稿（不调用模型）”，可从已保存响应恢复。恢复不清零累计预算；期限耗尽等情况不提供无效重试。

## 03 确认业务与测试目标

勾选业务后核对可编辑的中文预期和必要问题。AI回答可预填，清空或修改后应保留用户输入；每次修改仍需人工核对。点“已核对关键问题与业务预期”并“确认并保存项目规则”，保存的是精确规则版本，不自动编译、生成或运行。

基础检查按需展开。选择一条主操作，再为每项选择“不加入本轮”“加入检查，并确认上述预期”或“仅观察，不判对错”。仅选择操作名称不等于选择检查项；仅观察不升级为已确认业务，不提供负载达标资格。

“测试目标与补充说明”中选择正确性、目标负载或两者，保存实际目标和说明。没有本轮检查选择或来源有效的已确认业务时，“继续：检查运行条件”禁用；补选择或补业务确认，不能靠直接跳05绕过。

规则、方案版本或运行环境变化后，受影响确认须重新核对。保存失败或多标签冲突保留本页输入，由用户选择保留本页重新保存或加载已保存选择，不静默覆盖。

## 04 检查运行条件

沿用01的源码目录；更换目录在高级项内。选择自动生成两个普通测试用户，或展开手动账号填写本次凭据。核对独立合成数据副本、初始化和接口映射后，点击“检查并准备环境”，按准备面板确认并实际执行。

环境结果须显示登录及基线核验的实际成功或缺口。历史准备记录只证明原环境；宿主重启后密码会话失效，执行前须重新准备。缺初始化/映射时下载补充说明，不自动修改被测网站。

当前运行支持以已核对的Node24/Express5/Token/HTTP JSON/SQLite为限，不构成恶意代码的操作系统隔离。源码分析成功不证明网站可运行。

## 05 选择或生成检查方案

本页统一处理能力匹配、已有方案、新候选和06—08证据。页面显示可复用、可创建、待适配、待扩展或待澄清；这些状态不等于业务判定通过。

**已有方案**：核对适用/排除条件、精确版本及独立验证证据，选择并确认预期。停用版不会自动换成新版；不同证据损坏不能替其它版本背书。

**项目业务缺能力**：在对应业务卡片点击“准备这项业务的检查”。受控关闭契约只可绑定03已确认的工单关闭预期；标题修改不能套用，绑定不能替换预期。追加版本后须重新确认，再编译精确版本、选择本轮检查。无对应能力时导出缺口，不把自由说明当作可执行规则。

**需要新方案**：在对应规则卡片选择创建或重新生成。核对“创建方案前准备”中的接收方、候选生成材料与预算，再点“确认范围并创建方案”。候选上下文不同于02完整文件材料，发送同意不能互相替代。已有有效方案的查看、选择不调用模型；明确生成才调用。

06—08在05内更新，无需再分别启动执行器：

| 子步骤 | 核对内容 |
| --- | --- |
| 06 创建或适配检查方案 | 候选定义、修订与当前进度；出现候选不等于合格 |
| 07 独立验证方案 | 正常、已知缺陷、证据不足及留出/端到端对照；正确检出预置缺陷是准入证据，不是当前网站失败 |
| 08 在当前项目试运行 | 当前项目身份、映射、基线与取证是否适配；网站业务失败和候选是否有效分别记录 |

运行中的任务集中展示；不能重复启动新任务挤占当前任务。暂停按具体条件恢复；修订或预算耗尽不自动重置。已拒绝候选若提供“重新准备方案（新任务）”，先核对新预算并明确调用，旧任务原样保留。

全部所选项有有效方案时可“继续：执行检查”；新候选待审核则进入09。其它已选项缺方案时逐条补齐，不静默排除。

## 09 审核并确定方案

先查看方案做什么、独立正常/缺陷/证据不足、端到端及项目试运行证据，再核对“适用条件 / 排除条件 / 使用说明”。AI预填明确是参考，不能代替审核。

点击“保存本版审核材料”，由实际业务确认人和技术审核人分别核对职责、填写身份并确认，再点“审核通过，保存为可复用方案”。缺证据、未保存材料或缺任一确认时不能发布；材料修改使旧确认失效，须重新保存和审核。姓名输入不构成身份认证。

保存只进入本机方案库，不对外公开。首次发布且规则/环境摘要一致时可保留03已有确认；不能将仅观察选择或旧版本自动升级。09返回05查看准备，或继续10核对执行。

## 10 执行正确性与目标负载

10.1核对本轮规则、精确方案版本及运行环境，点“准备本轮检查”，在准备面板确认后“开始检查”。每次真实执行产生新运行；HTTP 200不代替业务性质判定。停止或证据不足保留对应状态，不能显示完整通过。

10.2是编号流程唯一负载启动入口。03先选择含目标负载的目标；所选规则的业务结果均有效、已确认并通过后才具备准入。11只查看、导出负载结果。

- **记录运行表现**：记录派发、等待和结果，不判断目标是否达标。
- **验证目标是否达标**：填写实际等待上限、允许错误比例及完整业务检查率/时长；缺阈值不能判达标。

界面允许1—100次完整检查/秒、1—300秒；达标模式等待1—300000毫秒、错误0—100%。所选规则占比合计100%，支持小数，“均分占比”处理三项舍入。次数单位是完整业务检查，不是裸HTTP RPS。

核对固定资源上限并勾选确认后，点“执行目标负载检查”。参数或外部03目标变化清除确认；已编辑时选择使用03最新目标或保留本页目标，解决冲突后再执行。

启动前完整核验，每次派发继续核对允许源码文件哈希和当前精确方案资格；来源变化或停用阻断。停止派发后有限结算在途实验，保留未知、压测端丢弃和停止原因。可下载负载报告及账本；本机短时结果不能外推生产、更高负载或最大容量。

## 11结果与12复测

在11选择对应运行，先查看本轮结论，检查项按“发现问题／尚不能判断／本轮通过／仅观察”分组。卡片保留固定预期、每条断言的预期值与实际值、证据引用和未覆盖原因；计划内未执行项不能算通过。“流程完成”不替代“业务通过”，旧报告不随最新候选改变语义。

先点“预览修复材料”，读取本次实际报告，再复制或下载同一份完整正文；读取失败可重试，切换运行不沿用旧内容。预览本身不执行检查、不调用模型、不发送给外部agent。“更多导出格式与备份”仍提供报告Markdown和验证包。材料区分计划步骤与实际执行记录，缺少动作或准备证据时明确标出复现材料不完整；不猜测根因，不附源码或私有答案，但业务观察仍需在分享前核对。

12仅在用户选择修复或复跑时启用。加载验证包先查看格式、项目与固定版本，不自动执行；明确准备复测、重新提供本次凭据后才运行。来源变化须重新接入、确认并补适配/验证/审核。当前有效方案复测不需要模型，重新生成方案另行确认。

修复业务实现或补齐条件后，点“我已修改项目或补齐条件，准备复测”，核对原范围、源码与映射变化及环境准备，再明确执行；不能删除检查或放宽断言制造通过。新记录以parentRunId关联旧运行，新旧报告保留，不自动应用外部修改。

关联复测的结果页展示上次／本次／结论，可展开两次实际值与证据、固定版本和数据基线，或返回原运行。只有同一规则与精确检查方法、映射、测试身份、数据和基线可核对且两次均完成时，原失败到本次通过才写“原问题在本次条件下未复现”。规则或版本变化、映射变化、数据或身份变化、缺记录、未知、仅观察、未执行和增删范围均按实际限制说明，不能直接判定修复。源码变化另行提示，不据此改写原证据。

## 数据保存与操作保护

已保存目标、说明、浏览位置及可选复测关联在宿主数据目录的 `journey/<projectId>.json`；检查选择与环境结果有各自版本绑定和保存机制。它们不是云端同步服务，不能将整份运行目录提交Git。

设置返回原项目/步骤；项目切换、刷新和重开按已保存状态恢复，不自动挑选项目或恢复执行同意。未保存输入不保证全部跨刷新/崩溃恢复；保存失败要处理提示。密码、Token不保存到工作流草稿或浏览器存储，API Key独立使用Windows凭据管理器或宿主会话，见[快速开始](QUICK_START.md)。

多标签写入检查修订号，保留冲突输入供人工选择。不得从后台轮询推断环境准备成功、覆盖正在编辑内容、恢复双审核勾选或外发授权。任务已完成后应查看结果，重新运行必须明确作为新执行。

| 情况 | 后续处理 |
| --- | --- |
| 材料超限 | 自行填写业务或选更小的独立项目；不假定当前界面有范围编辑入口 |
| 来源、规则或环境失效 | 查看具体变化，重新核对并补证据；导航不能解除阻断 |
| 模型不可用 | 可人工确认或复用已有有效方案；新生成仍需解决模型条件 |
| 会话失效 | 重连并保留可恢复输入，再手动重试操作；不自动重发审核/执行 |
| 原生核心或独立资源缺失 | 查看与设置仍可用；候选准入、执行和包复跑保持受阻 |
| 历史片段分析/旧包 | 保留可读；不标成全文件分析，不自动升级或继承执行资格 |

## 交互要求与验收标准

以下承接原自然流程设计的有效约束，也是[人工验收](MAIN_MANUAL_ACCEPTANCE.md)仍须逐项核对的标准，不表示全部真实设备测试已完成。

- 全新空库、无模型、已有方案、仅分析、缺能力和多规则路径应给出准确下一步，不自动调用或静默缩减选择。
- 未保存材料、来源变化、停用、跨标签冲突、重复点击、后台完成和刷新不应丢失已保存数据或绕过资格。
- 历史报告绑定原运行；预期、实际和来源可追溯，缺值写未取得，不猜测业务影响；时间显示本地可读格式并可查原时间。
- 界面收起不常用技术详情，禁用动作附近解释缺项；成功、失败、未知和仅观察不能只靠颜色区分。
- 步骤使用aria-current，详情关闭返回触发位置；设置往返、浏览器前后退及刷新保留正确任务，轮询不夺焦点或滚动输入位置。
- 报告标签支持键盘切换及关联内容区，核心操作Tab可达且焦点可见，状态播报只在有意义的变化时更新。
- 核对1280、768、390宽度、1920×1080及200%缩放的操作可达性、对比度、抽屉和键盘/读屏；不能用尺寸检查代替全部人工验收。

真实模型质量、实际人员双审核、原生窗口、完整可访问性、正式新目录交付与T10继续按独立要求验收。已有开发成绩与本轮四阶段专项验证见[证据索引](evidence/README.md)；专项通过不能代替完整产品及正式人工验收。
