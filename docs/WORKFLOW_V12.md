## 主流程

01 导入项目：只索引源码，不要求账号，不调用模型。
02 了解与分析业务：按提示词分析或自动梳理业务；也可显式跳过，自行确认业务。
03 确认业务与测试目标：保存人工业务说明草稿，确认项目规则，选择正确性、目标负载或两者。
04 检查运行条件：独立副本、账号、测试数据、接口映射及运行环境。
05 匹配方案与支持能力：可复用、可创建、待适配、待扩展、待澄清。
06 创建或适配检查方案：保留现有候选生成及受控执行链路。
07 独立验证方案：查看正常、错误及证据不足对照。
08 在当前项目试运行：查看当前项目适配证据。
09 审核并确定方案：保存说明并完成业务及技术审核。
10 执行正式检查：10.1正确性；10.2已选负载，仍须通过后端准入且明确启动。
11 结果、导出与保存复用：可导出报告、外部修复报告和验证包，然后结束。
12 修复与复测：独立可选分支；不启用不会阻塞11，复测后返回11。

原13已并入11。保存历史不等于取得未来复用资格。
导航不触发模型或执行；后台轮询不改变当前所查看的步骤。
候选生成仍沿用既有的自动验证/试运行状态机，07与08是分开的证据视图，
并非新增两套重复的执行器。

## 各步骤的条件、产出与后续动作

下表描述当前实现的操作含义，不代表这些路径均已完成真实浏览器或Windows验收。
“查看下一步”只是导航；操作是否允许，以服务端准入和当前证据为准。

| 编号 | 进入操作所需条件 | 本步产出及完成含义 | 后续动作或阻断处理 |
| --- | --- | --- | --- |
| 01 | 可读取的源码目录，或选择已有项目 | 项目标识与源码快照；不代表环境可运行 | 去02；仅了解项目时可不准备执行环境 |
| 02 | 已保存分析范围；使用AI还需模型配置及发送确认 | 带引用的业务建议与待澄清项；不自动确认为正确需求 | 去03核对；可明确选择跳过AI、自行确认 |
| 03 | 业务预期可明确描述；项目规则需确认对应版本 | 保存业务说明、规则确认和测试目标；说明草稿本身不可执行 | 缺预期先澄清；执行前继续04 |
| 04 | 独立运行副本、测试账号/数据及接口映射 | 对当前环境版本的准备记录 | 补齐缺项后去05；只导入源码不能直接运行 |
| 05 | 所选规则与对应能力评估 | 可复用、可创建、待适配、待扩展或待澄清 | 用户主动前往对应编号，页面不自动跳转 |
| 06 | 可复用精确版本，或具备生成/适配条件 | 候选或所选方案；候选存在不等于通过 | 查看07、08证据，不绕过审核 |
| 07 | 已有独立验证记录 | 正常、错误与证据不足对照的验证证据 | 证据不满足时修正方案；不能只验证“能跑” |
| 08 | 当前运行环境及候选试运行记录 | 对当前项目身份、接口和观察的适配证据 | 不适配则返回04/06补齐，不继承旧环境结论 |
| 09 | 独立验证、试运行等准入证据 | 业务/技术审核记录与固定方案版本 | 未满足审核条件不能通过导航获得执行资格 |
| 10 | 有效方案、规则确认及运行条件；负载另有准入 | 新运行记录；10.1正确性，10.2目标负载 | 必须明确启动；执行结束后主动查看11 |
| 11 | 选中对应运行；失败或部分结果也可查看 | 报告、外部修复报告或验证包；历史证据保留 | 可直接结束；需要修复时主动启用12 |
| 12 | 用户选择修复及原运行 | 关联原运行的新复测记录 | 有效方案可复测；失效先补适配/验证/审核，再回11 |

### 常见路径与跳过规则

- 有有效方案：01 → 03 → 04 → 05 → 核对已有06/07/09证据及当前项目适配 → 10 → 11。02可人工跳过；历史证据必须仍适用。
- 没有方案但具备能力：01 → 02或人工确认 → 03 → 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11。
- 缺少执行能力：到05保留“待扩展”和未覆盖原因，导出能力缺口后停止该业务的执行准备。其他已具备条件的业务不因此自动取得资格。
- 只想了解业务：完成01—03即可停止；未执行的后续步骤不标作业务通过。
- 外部修复：11导出 → 用户交给外部agent修改 → 主动进入12核对变化/复测 → 11查看新旧记录。

这里的“跳过”指不重复执行不需要的工作，编号仍保留。系统没有一个允许用户任意将所有步骤标成通过的开关。
07与08主要展示现有候选流程生成的证据，不要求为每个编号再启动一套执行过程。

## 界面与状态

左侧为全部固定编号，中间为本步工作区；“查看本步骤说明与证据”打开右侧面板。
当前查看与后台进度分开。状态不等同于业务结论。
源码项目也能浏览后续步骤；未具备运行条件时，不能凭浏览或规则草稿执行。
模型设置保留返回的具体编号。
浏览位置按项目保存；重新选择项目时恢复该项目位置。
保留URL可恢复同一项目及运行；新开无参数工作台仍需选择项目，不自动挑选用户项目。

范围、目标、提示词和审核材料有各自明确保存操作。
步骤间切换保留挂载中的输入；已保存提示词、业务说明及目标在宿主重启后保留。
未保存输入不会全部自动写磁盘，刷新/离开有未保存提示；密码不写浏览器存储。
目录输入只在浏览器会话中暂存。系统崩溃时，不能承诺恢复所有未保存输入。

### 如何解释状态

- “已完成”：对应流程动作完成。例如10完成仍可能得到业务失败报告。
- “已有证据满足”：复用特定版本证据，并非本轮重新测试通过。
- “可查看”：有内容可查，不代表内容合格或审核通过。
- “已跳过”：用户明确跳过AI分析，不保证业务已穷尽。
- “已阻断”“已失效”：应阅读原因并补条件或重新核对，不应强行继续执行。
- “可选 · 未启用”：12未开启，是正常结束状态，不是遗留必做事项。

## 完整文件分析

新界面先保存范围，再预览完整材料，最后确认发送。
确认绑定快照、范围、服务地址、模型、提示词及文件摘要，变化后拒绝旧确认。
新分析首次请求包含全部预览的允许文件，无模型按需取片段动作。
历史片段分析会话仍可读取与恢复，不能标作全文件分析。

允许的常见文本包括JS/TS、JSON、MD/TXT、Python、Java、Cangjie、Go、Rust、
Vue/Svelte、HTML/CSS/SCSS、SQL、YAML、TOML及Shell/PowerShell。
非JS/TS只读取正文，不宣称完成语法关系解析。
密钥、数据库、依赖、构建产物、二进制、私有验证资源和越界链接仍被排除；
项目测试须显式纳入。秘密检测不能保证识别所有秘密。

本轮有界实现：
- 单文件及正文总量上限均为65536字节。
- 包含协议开销的实际请求仍受98304字节上限约束；预览使用更保守估计。
- 继承8次请求、10分钟及120000 token累计预算，恢复不重置。
- 超限阻断并说明原因，不截断、不摘要、不自动分批。
- 上述是平台预算，不等于模型真实上下文或具体货币费用承诺。

输出保留事实、文档/测试预期、AI推断及引用，并增加前置条件、
异常分支、状态变化和待澄清问题。自动梳理不保证穷尽所有业务。

## 哪些操作使用AI

| 环节 | 是否需要模型调用 | 模型输入与产出 |
| --- | --- | --- |
| 01导入、03手动确认、04环境配置、05能力评估 | 不需要 | 本地索引、规则、环境及确定性能力判断；用户操作本身不调用模型 |
| 02完整文件业务分析 | 用户选择AI时需要，可跳过 | 输入确认范围内允许文件的完整正文、来源信息和提示词；输出带引用的业务概览、预期、异常、状态变化与待澄清项 |
| 06生成新候选 | 使用现有AI候选生成入口时需要；复用已有有效方案不需要 | 输入候选生成专用上下文和受控任务约束，输出待验证候选。此路径不承诺复用02的全部文件输入；具体发送范围依现有候选协议 |
| 07独立验证、08试运行、09人工审核、10执行 | 检查及审核本身不需要模型裁决 | 执行器、对照资源及人工审核形成证据；AI建议不能替代这些结论 |
| 11导出、12沿用有效方案复测 | 不需要 | 导出已有记录或运行确定性复测。若需重新生成候选，返回06可能再次调用模型 |
| 模型设置“保存并检查连接” | 会调用模型 | 最小连接检查，不是业务分析；“保存到本机”则不发起模型请求 |

“全部文件”准确含义是全部**已确认范围内、允许读取且允许发送的文本文件**，不是整个磁盘或未经筛选的仓库。
预览后发现范围、源码、模型接收方或提示词变化，应重新预览并确认。未确认前不能把源码发送给模型。
自动梳理只是尽可能发现业务，不是“证明找出了所有业务”。模型输入含源码时应先核对接收方及数据授权。

## 新业务与外部修复

自由业务说明只是需求草稿。项目特有建议经用户确认仍须经过能力评估。
缺少可信操作、观察、断言或独立验证资源时，保留待扩展/未覆盖状态；
可导出本地能力缺口，不自动外发或让模型修改执行器。
本轮没有增加通用任意业务执行、任意外部模板导入或多业务并发调度。

11的外部修复报告包含规则、固定版本、复现步骤、观察、判定、
证据引用、未覆盖与复测说明；不附带源码及私有验证答案。
用户自行向外部agent交接。有效方案复测不依赖平台模型；
方案失效时仍须补适配、验证与审核，不能以修改断言制造通过。
复测使用原有parentRunId关联，新旧报告均保留。当前对比采用关联运行切换查看，
尚未实现逐字段并排差异表。

### 外部agent交接操作

1. 在11选择对应运行并导出“外部修复报告”，先检查其中的观察、路径和业务信息是否适合分享。
2. 自行将报告及必要项目材料交给所选agent；平台不会自动发送文件或配置外部agent。
3. 要求修复业务实现，保留原测试目标；不能通过删除检查、放宽断言或隐藏失败制造通过。
4. 修复后在12检查源码、环境、规则及方案版本变化。若原证据失效，先补做对应步骤。
5. 明确启动复测；新记录通过parentRunId关联原记录，返回11分别查看。旧通过不自动继承，新记录不覆盖旧报告。

报告不附带源码和私有验证答案，但仍可能含业务观察信息；“不含源码”不等于可以无审查地公开发布。
当前提供关联运行切换查看，不提供逐字段并排差异表，也不自动应用外部agent修改。

## 数据保存与失败处理

已保存工作流偏好位于宿主数据目录的`journey/<projectId>.json`，包含目标、提示词、说明、浏览位置及可选修复关联。
它不是源码文件，也不是云端同步服务；不要将整个运行数据目录提交到Git。
API密钥的保存方式独立于这些偏好，见[本地API设置](QUICK_START.md)。

| 情况 | 应如何处理 |
| --- | --- |
| 完整材料超限 | 缩小并明确保存分析范围，再重新预览；不会静默只发送前一部分 |
| 多标签保存发生修订冲突 | 核对已保存版本和当前输入，再决定保留哪份；不要假定后保存总会覆盖成功 |
| 浏览位置后台保存失败 | 页面仍可切换；下次可能恢复旧位置，不能据此推断业务数据已丢失 |
| 源码、环境或规则证据失效 | 核对变化并补相关验证；不能以改导航状态解除后端阻断 |
| 模型不可用 | 可自行确认业务或使用已有有效方案；需要重新生成候选时先解决模型条件 |
| 缺少Windows原生核心 | 可以查看工作台和保存设置，但不保证执行、候选准入或验证包复跑可用 |
