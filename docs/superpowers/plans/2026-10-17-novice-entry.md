# CangJie 第三阶段：支持范围与示例体验实施计划

Goal: 在导入后立即提示静态支持情况，提供独立工单练习副本与真实新手试用材料。
Architecture: 复用inspectProject的保守静态检查和原source-projects导入；示例只复制已有工单源码，用户明确导入后仍走原四阶段、授权、验证和关联复测。
Spec: 本聊天已认可《CangJie 新手界面与流程简化方案》第14节第三阶段：更早的支持检查、示例体验、真实新手试用与针对性优化；本轮用户明确授权执行。

## 边界与决定
- 沿用当前工作目录和前两阶段未提交修改，不提交推送；不改变现有资格、模型发送、环境授权及审核。
- 静态核对只读取本机文件，不创建运行/凭据或发送模型，不替代实际准备。支持提示不用于授予执行资格。
- 示例明确点击才创建独立源码副本；不预造结果、不自动导入/运行或注入合格方案/审核。沿用现有工单能力，不引入新技术栈或演示执行系统。
- 没有真实参与者时只能交付试用任务和记录，不能宣称新手验收完成；建议5人、至少4人独立完成及关键边界零误解仍为待取得证据。

## 任务
- [x] 支持检查：新增只读project-support接口，复用inspectProject，返回符合静态条件／缺配置／超出自动准备范围及原缺项材料。先测试支持项目、缺配置、超出范围、缺项目与状态不变。
- [x] 示例体验：明确准备独立工单副本，保留原样例，返回可导入路径；界面不自动导入或执行，保留路径输入、错误和取消。验证无确认拒绝、固定来源、安全复制、独立多次创建和真实导入。
- [x] 导入页简化：当前项目与支持结论靠近继续入口，错误可重读，切项目或刷新索引取消旧响应；示例标明练习来源，继续业务整理不受静态检查失败阻断。验证读取中/失败/切换/窄屏/无自动执行。
- [x] 构建及单元、相关API/浏览器回归，独立只读审查，保留证据，更新体验说明、新手试用任务和档案；实际新手试用单独留待反馈。
- [ ] 真实新手按任务独立试用，取得耗时、求助和边界理解记录，再依据反馈实施必要优化（当前无参与者数据，不计通过）。

Review focus: 同一项目源码重新导入；切换项目迟到响应；示例准备后旧项目继续入口不能指向错误项目；本机副本不描述为安全沙箱；静态通过不标成可运行或网站通过。

执行记录：采用本会话直接实施，沿用现有main本地开发约定；不另建工作树，以保留前两阶段尚未提交修改。真实新手试用不以自动测试替代。
