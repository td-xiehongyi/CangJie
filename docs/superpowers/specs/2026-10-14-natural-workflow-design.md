# 自然操作流程改造方案

日期：2026-10-14
状态：用户已授权实施；源码改造及自动化验收完成，真实设备及正式验收限制见[验收记录](../../evidence/natural-workflow.md)。
依据：[当前版本交互审查](../../../output/ux-audit-2026-10-14/交互审查.md)

## 目标与方案选择

让首次使用者和返回用户随时知道：正在检查哪个项目、已完成什么、还缺什么、下一步做什么。保留现有蓝白四页、可信验证链、版本固定与双重审核。

选择“现有四页内统一任务主线”：相比仅改文案，它能解决刷新丢状态和入口绕路；相比重建全屏向导，它保留历史报告、项目切换及高级用户自由导航，改动更集中。

本轮不改判定算法、模板准入要求和资源预算；不新增账户系统、多人协作平台或模板商城，不更新正式验收副本、不重新打包、不提交或发布。目录选择、表单草稿和证据摘要都是为现有操作服务。

## 一、统一主线和页面分工

主线固定为：接入项目 → 选择检查 → 准备方案 → 运行检查 → 查看结果。

- 项目接入负责选择本机项目、条件检查、环境准备；AI推荐作为可选辅助。
- 业务验证负责选择本轮检查、缺失方案的创建与审核、执行进度。
- 验证报告负责业务结论、证据、复测、负载验证；“检查方案审核”改为“方案与验证依据”，审核仍回业务验证办理。
- 模型设置是可返回原任务的支线，不作为所有用户必须经过的步骤。
- 有合格匹配方案时，第3步显示“已有可用方案”，无需重新生成。缺方案的规则明确标记“待创建/待审核/受阻”。
- 单一进度组件显示当前步骤、已完成项和阻断原因；不让不同页面的相同编号代表不同含义。候选的生成、自动验证、人工审核只作为第3步内部状态。
- 历史报告绑定原运行；返回当前任务继续操作，不把历史运行误当作本轮进度。后台轮询不夺焦点或改变用户正在查看的报告。

## 二、接入与准备

### 入口

标题为“选择本机网站项目”。项目目录旁提供“选择文件夹”，保留直接粘贴路径；用途字段保留示例。目录选择通过受保护的本机宿主调用Windows选择器，仅返回目录路径，不上传整个文件夹。取消选择不报错；选择器不可用时明确提示粘贴完整路径。不把浏览器文件上传或相对目录名伪装成宿主绝对路径。

首屏说明“需要可启动的网站源码及测试配置”。具体兼容性以当前检查器返回为准；不暗示任意网址或任意框架已支持。自动测试账号保持默认，手动账号展开后填写。

### 识别后

按顺序展示：项目摘要 → 条件检查结果 → 下一步。缺少条件直接列出影响与补充操作，技术详情和下载说明作为补充。

移除固定默认的“直接选择已有检查方案”单选；显示当前匹配情况。空库写“还没有可用检查方案，可先选择要检查的行为，再创建方案”；存在匹配方案写“有可复用方案，选择检查后核对适用条件”。全局库数量不能冒充当前项目可直接运行数量，最终以规则、接口能力和版本资格校验为准。

AI辅助入口为“让 AI 推荐检查内容（可选）”。无模型配置时进入设置，返回原任务；实际发送仍展示范围并获得必要确认。

### 环境状态

分开记录“同意使用测试环境”与“环境准备实测结果”。宿主保存最近准备的时间、条件指纹、结果和可解释错误；前端不能用用户勾选或AI分析成功推断环境准备成功。

准备成功：显示“最近一次环境检查通过，两个测试用户登录成功”，主按钮“继续选择检查”。源文件、映射、账号条件变化后标记需重新检查。重启后可展示历史成功，但运行时仍重新校验会话凭据与当前条件，每轮照常准备独立数据。

## 三、规则选择和草稿恢复

每条规则展示：加入本轮、预期行为、方案状态。选中后展开“确认这是预期行为”；未确认时标记“只观察，不判对错”。开始前汇总“X项判定、Y项仅观察”，让用户明确本轮输出类型。

缺方案时按依赖顺序给出一个可执行动作：确认规则 → 设置模型（如缺）→ 核对发送范围（如需）→ 创建方案 → 审核方案。多个规则缺方案时列清单和各自状态，保持所有选择，逐条处理；不得静默缩减运行范围。

由本机宿主持久化每项目/流程的工作草稿：流程、所选规则、规则摘要、精确方案版本引用、规则业务确认及其条件指纹。前端切换/刷新恢复，展示保存中/已保存/保存失败。保存失败不假装可恢复；重试保留本地输入。

草稿变更带修订号，防止多标签页和晚到请求覆盖更新；冲突时保留当前编辑并提示刷新核对。轮询不能覆盖未提交的输入。

有效性规则：规则语义或方案版本变化清除受影响的规则确认；项目条件变化提示重新核对。已停用版本不自动换成最新版。不保存密码、Token、API Key到草稿；不自动恢复双审核勾选、外发授权或负载执行确认。既有审核材料继续使用原保存机制，显示未保存状态，离开前提供保存或放弃选择。

## 四、设置支线与页面导航

设置入口携带项目、原页面和待办动作，例如“正在为工单项目创建提交保存方案”。

- 从创建方案进入：连接成功后显示“返回检查方案”。
- 从AI推荐进入：连接成功后显示“返回项目分析”。
- 从侧栏独立进入：显示“模型连接已就绪”，不强行导航。

返回只恢复任务上下文，不自动调用模型或执行检查。返回目标采用应用内枚举，不接受任意外部地址。配置失败给出可理解原因和字段定位，保持原任务选择。

主导航切换将焦点移动到页面标题并显示顶部；设置往返可恢复原任务位置。浏览器前进后退与URL项目/运行标识保持一致。表单输入期间的轮询不滚动页面。

## 五、方案审核

审核区依次为：

1. **方案做什么**：规则、执行步骤及适用范围；AI说明明确标记“参考，待确认”。
2. **验证证明什么**：正常样例、已知缺陷样例、证据不足样例、端到端验证、项目试运行分别列出预期与实际结论及证据入口。
3. **材料编辑**：适用条件、排除条件、使用说明；版本默认建议值，版本调整放次要位置。
4. **业务确认**：确认预期行为和适用范围，填写确认人。
5. **技术审核**：确认定义、验证证据和限制，填写审核人。
6. **保存为可复用方案**：保留保存材料后再双确认的机制，所有条件齐备后启用。旁边注明“保存到本机方案库，不对外公开”。

验证摘要来自已有记录，不再额外调用AI。已知缺陷被正确检出应显示“成功检出预置问题”，避免红色fail被误解为方案不合格；证据不足被正确识别也需解释。不把“方案验证通过”写成“网站业务通过”。原始JSON仍可查看。

没有技术审核人时保留待审核状态，提供明确交接说明和证据查看入口，不让业务用户冒充技术审核。此轮仅优化既有责任呈现，不宣称文本姓名实现了身份认证。

发布成功后主动作“准备运行所选检查”；其它已选项未就绪时显示剩余清单，不重复创建已经就绪的方案。

## 六、状态与主按钮

| 状态 | 首屏重点 | 主动作 |
| --- | --- | --- |
| 项目未识别 | 路径与用途 | 检查项目 |
| 环境缺条件/失败 | 缺什么、如何补 | 修复后重新检查 |
| 环境检查通过 | 项目摘要和下一步 | 选择检查内容 |
| 未选择规则 | 业务行为列表 | 选中后继续 |
| 已选规则缺方案 | 缺失清单 | 准备缺失方案 |
| 方案生成或自动验证中 | 当前阶段 | 显示进行中，禁止重复触发 |
| 等待人工审核 | 证据摘要和职责 | 完成审核 |
| 本轮已就绪 | 所选范围、判定/观察摘要 | 开始检查 |
| 运行中 | 进度置顶 | 查看进度；停止为次操作 |
| 本轮已完成 | 结果摘要 | 查看检查结果 |
| 中断/受阻 | 原因及已保留内容 | 满足恢复条件后继续/重新准备 |

“继续”只用于未完成任务；新执行明确标成“重新运行”。已完成时收起旧准备动作。已有运行的查看报告操作不触发再次执行。前端防重复点击，宿主继续承担并发与状态校验。

## 七、报告与负载

报告标题和操作随结论变化：

- 通过：“本轮所选检查通过”，主动作“选择其他检查”；负载验证为次操作。
- 失败：“发现 X 项业务问题”，主动作“复制问题说明”；“修复后复测”作为明确后续动作。
- 无法判断：“X 项缺少验证条件”，直接列出缺项与恢复入口。
- 仅观察：“已记录行为，尚未判断对错”，提供核对规则入口。
- 仍在运行/已中断：不能展示完整通过结论，即使部分断言通过。

失败详情提供预期、实际、证据和修复后复测范围。只显示真实记录中可定位的值；缺失时写“未取得”，不能根据错误码或AI猜测业务影响。预期/实际值绑定断言与观察记录，保持来源可追溯。时间使用本地格式；原始时间与ID进入详情。

目标负载仍放在业务报告中，具备资格后展开。改成“每秒运行多少次完整业务检查”“持续时间”“允许错误百分比”。UI输入百分数，提交前转换为现有0—1口径。

明确两个模式：记录运行表现（不判达标）；验证目标是否达标（必须提供等待上限及错误标准）。不默认替用户设业务阈值。多规则提供“均分占比”，显示合计并要求100%；编辑参数后重置执行确认。保留当前固定预算、停止结算和同机结果边界，不扩展最大容量结论。

## 八、布局和可访问性

收紧顶部留白和项目摘要；当前操作置于首屏，已完成详情默认折叠。长表单底部提供跟随内容的操作区，在窄屏不遮挡输入及焦点。禁用动作旁写明具体缺项，不只给灰按钮。

步骤使用文本完成标记和 aria-current；报告标签补齐tabpanel关联及方向键操作；主导航、错误摘要、设置返回管理焦点。状态播报只在有意义的阶段变化时更新。正文/辅助文字、按钮和焦点指示做对比度实测。1280、768、390宽度和200%缩放检查布局及键盘可达性。

## 十、验收场景

1. 全新空库、无模型：先知道缺方案，可以先选检查，去设置后准确返回，不丢选择。
2. 已有有效方案、无模型：不要求配置AI即可完成本轮；不能把不匹配方案当可用。
3. 不使用AI准备成功：刷新/返回仍展示真实准备记录；重启及条件变化按实际状态重新校验。
4. 多规则、切换流程、项目切换、刷新及重开：恢复各自草稿；过期确认和停用版本不自动沿用。
5. 多标签编辑、保存失败和轮询：不能静默覆盖或错误提示已保存。
6. 审核材料修改：重新保存、重新确认；缺技术审核仍阻断；预置缺陷被检出不显示成方案失败。
7. 连续点击、运行中导航、完成后返回：只有一次执行，主动作正确进入原运行报告。
8. 通过/失败/未知/观察/中断报告：结论与动作相符，值及证据可追溯，历史报告不被新候选替换语义。
9. 负载百分数、空阈值、比例总和、参数变化：模式与判定准确，后端预算不变。
10. 三种宽度、200%缩放、全键盘与焦点：无关键操作遮挡，状态不限于颜色传达。

实施验证采用定向集成和浏览器回归，随后完整 npm test、npm run check；隔离样例与真实验收分开记录。真实模型/实际双审核及8098原验收待办不因本方案自动关闭。
