# 工单提交样例

仅用于本机合成数据验证：工单提交、重复提交去重、私有查询和标题修改。修改标题时优先级与归属应保持不变。


## 基础界面与独立演示

需要 Node.js 24。在仓库根目录安装依赖后，进入本样例目录执行：

```sh
npm run demo
```

终端输出本机访问地址、demo-owner / demo-other 两个账号及本次随机密码。打开地址，输入测试凭据；不要使用真实密码。默认选择空闲端口，也可通过 PORT 指定本机端口。

页面提供登录/退出、创建、我的记录列表、刷新和修改操作；状态样例提供关闭与“尝试重新打开”动作。页面调用现有真实业务接口，不使用伪造成功结果。没有生产注册、支付或找回密码功能。

- 重复点击“提交”沿用相同提交意图，用于观察去重；创建另一条请点“新的提交”。
- 切换账号保留演示批次，可核对数据隔离。刷新保留批次，但清除页面内存中的登录令牌；密码和令牌不存入浏览器持久存储。
- 高级区域可切换演示批次。列表按当前账号和批次查询，不显示其他批次；刚开始为空是预期行为。
- 输入内容按文本渲染，HTML字符串不会作为页面代码执行。服务只监听127.0.0.1，不是生产部署配置。
- 每次演示建立新的系统临时数据库，不接受外部TEST_DATABASE覆盖。正常退出（Ctrl+C）删除此临时目录；强制终止或断电可能留下临时数据，新一轮不会自动复用。
- 原 `npm start` 和 `initialize:test` 仍用于验证器提供的显式隔离配置；不要手动将其指向真实数据库。

`src/ui.ts` 保存页面与样式，`src/public/app.js` 保存客户端行为；全部在本目录内，独立副本不依赖其他样例。验证器只复制已支持的源码扩展名，因此没有增加无法复制的独立HTML/CSS资源。

开发验收范围见仓库 `docs/evidence/sample-websites-2026-10-16.md`；界面操作成功不替代业务规则验证与正式验收。
