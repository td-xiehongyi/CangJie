## 无模板主线

1. 确认“只修改标题时，优先级和所有者保持不变”。未勾选不能继续。
2. 检查能力：本例缺实验，已有登录、创建、更新和完整查询原语。
3. 生成 v0.1 草稿；受约束步骤和断言可展开，尚未发布或执行正式项目验证。
4. 开始验证：正常、优先级重置、所有者改变、缺最终字段分别核对。所有者的包含关系断言漏检，候选不准入。
5. 修订 v0.2：严格相等，独立样本重新核对；首次生成后最多两轮修订，次数与原因保留。
6. 受控 HTTP 端到端：按冻结、开发者审核的正确及缺陷参考版本验证；隐藏变体不向生成器泄漏答案。
7. 项目副本试运行：身份、对象、完整查询及复位复跑有效，但网站优先级被重置。模板有效与网站业务失败同时保留。
8. 提交审核：业务适用确认和开发者技术审核都勾选，才能发布固定 v1.0；可查看证据或退回草稿。
9. 修复后复测：核对环境、隔离旧操作、恢复基线，从第一步执行，新建 R015 关联 R014，不覆盖旧证据。
10. 复测通过后进入目标负载；“切换示例”还可查看第二项目仅修改接口、字段和查询映射的复用。

缺映射回接入；缺底层执行能力保留开发缺口；规则待定回规则确认；无可信对照保留草稿，不能发布；三次尝试耗尽不自动重置。

## 目标负载主线

确认操作率、时长、P95 与错误率阈值，使用方式只展示本例均匀编辑。默认 60 次/分钟 × 10 分钟，预算上限和停止条件折叠；不能超过有限内部预设。

低负载业务通过 → 目标确认 → 运行 → 停止派发 → 查询在途最终记录 → 业务与性能共同满足且证据完整才判目标通过。意图、尝试、接受和最终记录分开显示；600 次意图可能对应 612 次请求尝试。

业务违规、持续性能超标、资源上限和人工停止均先停止派发并结算，结论分别保留业务失败、目标未达标或未完成。结算超期保留无法验证。本机环境和本次检查范围保留，不外推线上或最大容量。

## 验证包主线

顶部“加载验证包” → 选择示例包 → 格式/摘要、引用路径、解释器版本、模板资格检查 → 重新输入测试密码 → 确认模板适用、环境、旧写操作隔离和基线 → 从第一步复跑 → 新报告关联历史。

停用 v1.0 不能直接执行；可选有效 v1.1 后重新确认，新记录使用 v1.1，原包引用和 R014 保留。包被改动或版本不兼容没有绕过执行入口。包不包含 Key、密码、Token 或隐藏答案；无需 AI 重新探索的有效实验可直接复跑。
