# 工单标题更新业务：两组共同输入

这是本机合成工单网站，Node.js 24、Express 5、SQLite、HTTP/JSON、Token 登录。
主流程：用户登录 → 创建工单 → 修改标题 → 查询保存结果。

业务要求：标题更新应被实际保存，工单 ID、所有者和优先级应保持不变；另一个普通用户不能读取或修改该工单。接口成功不替代查询取证，取证不足应明确说明。

接入材料：本组获得的项目目录及其中的 verification.json。两个合成账号为 alpha/user-a 和 beta/user-b，角色均为 user。操作者在本机设置测试密码，不写入报告。
初始条件：ticket-seed-v1，两个账号、两条基线工单；每组分别初始化独立数据库，不能共用运行数据。初始标题为“初始标题”，更新值为“更新标题”。

任务：检查上述业务，保存可复现的结论与证据。之后操作者会提供一个统一的待复测版本；使用相同初始条件和你保存的成果复测，说明原结论是否仍成立。
可使用本组提供的实际执行工具，不接受只有测试建议但没有运行的结果。若受阻，保存原因、未完成项及已经获得的证据。

双方使用相同服务和明确填写的模型名称，不自动更换模型。预算、计时和取证约定由操作者在开始前统一告知。不要读取另一组结果或开发者私有验收材料。
