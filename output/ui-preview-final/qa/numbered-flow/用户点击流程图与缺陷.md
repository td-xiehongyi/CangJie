# 用户点击流程图与当前预览缺陷

2026-10-12。本轮只说明、编号和审查，未修改四页源文件。蓝色数字表示用户操作；圆角“系统”节点表示自动处理，不是要求用户再点一次。A1—A8 是异常恢复分支。输入、可选折叠详情与必要确认归在相邻操作步骤内。

## 一、模型与项目接入

```mermaid
flowchart TD
  startNode([首次使用]) --> a01["01 模型设置：填写地址、模型、API Key"]
  a01 --> a02["02 检查连接"]
  a02 --> modelCheck([系统：检查连接与结构化输出])
  modelCheck -->|通过| a03["03 保存并返回项目"]
  modelCheck -->|失败| a01
  a03 --> a04["04 选择目录，填写用途与测试账号"]
  a04 --> a05["05 调整发送范围，勾选同意"]
  a05 --> a06["06 确认测试副本与专用测试数据"]
  a06 --> a07["07 开始分析，再查看检查结果"]
  a07 --> accessCheck([系统：准备环境、身份、数据和接口])
  accessCheck -->|缺初始化| initCopy["A1 复制补充说明"]
  initCopy --> initRecheck["A2 补齐后重新检查"]
  initRecheck --> accessCheck
  accessCheck -->|缺取证| queryInput["A3 补充取证信息"]
  accessCheck -->|缺测试服务| gapCheck["A4 配置测试服务并重新检查接入"]
  queryInput --> gapCheck
  gapCheck --> accessCheck
  accessCheck -->|条件满足| a08["08 确认接口、身份、字段并试运行"]
  a08 --> a09["09 选择业务流程；需要时更换"]
  a09 --> a10["10 编辑并勾选已确认的业务规则"]
  a10 --> a11["11 确认并检查能力；已有模板则验证"]
  a11 --> templateChoice{有适用模板吗}
  templateChoice -->|有| businessRun([系统：按所选检查执行业务验证])
  templateChoice -->|没有| candidateEntry([进入第二图 12])
  templateChoice -->|规则待定| observeOnly([只观察，不判对错：当前预览缺 F5])
```

本轮复现：02→03 默认预览无法自动继续，属 F1；04→05 调整范围会重置无关表单，属 F2。A1—A4 为当前源文件中的异常入口，本轮未对每种实际接入条件进行识别或真实检查。

## 二、无模板候选到审核发布

```mermaid
flowchart TD
  candidateEntry([没有适用模板]) --> prerequisites{缺哪一类条件}
  prerequisites -->|缺映射| remap["返回 08 补映射并试运行"]
  prerequisites -->|规则未定| rulesBack["返回 10 确认规则"]
  prerequisites -->|缺底层能力| capabilityGap([保留缺口，暂停受影响检查])
  prerequisites -->|执行能力足够| a12["12 生成候选"]
  a12 --> a13["13 开始验证候选"]
  a13 --> candidateCheck{定义及独立对照检查}
  candidateCheck -->|漏检或误判| a14["14 修订并重新验证，最多两轮"]
  a14 --> candidateCheck
  candidateCheck -->|次数耗尽| exhaustedNode([保留草稿和原因，不发布])
  candidateCheck -->|正常及缺陷对照通过| a15["15 运行受控端到端"]
  a15 --> referenceCheck{可信对照齐全且有效吗}
  referenceCheck -->|否| copyReference["A5 复制待补要求"]
  copyReference --> checkReference["A6 补齐后重新检查"]
  checkReference --> referenceCheck
  referenceCheck -->|是| a16["16 在项目副本试运行"]
  a16 --> a17["17 提交审核"]
  a17 --> a18["18 查看验证证据，确认业务适用"]
  a18 --> a19["19 开发者勾选技术审核"]
  a19 --> a20["20 审核并发布固定版本"]
  a19 -->|依据不足| rejectCandidate["A7 退回候选，保留原因"]
  rejectCandidate --> checkReference
  a20 --> publishedNode([固定版本发布；项目业务失败继续保留])
```

18 与 19 缺一项，20 均不可发布，本轮重新点击核对。15—16 的验证结果是固定示例，不是实际参考服务执行。本轮未逐一重测缺原语、次数耗尽、模型中断及预算耗尽的恢复执行。

## 三、报告、修复复跑和目标负载

```mermaid
flowchart TD
  reportEntry([本轮验证报告]) --> a21["21 切换业务结果与候选资格"]
  a21 --> resultChoice{业务结果}
  resultChoice -->|业务失败| a22["22 展开请求与断言、完整证据、复制修复说明"]
  a22 --> outsideRepair([用户或编码 AI 在工具外修复])
  outsideRepair --> a23["23 修复后复测"]
  a23 --> a24["24 核对修复目录、版本和本次变化"]
  a24 -->|接口变化| remapNode["08 重新确认映射后返回复跑准备"]
  remapNode --> a25
  a24 -->|映射未变| a25["25 补密码，确认版本、环境、隔离及复位"]
  a25 --> a26["26 准备完成，开始复跑"]
  a26 --> replayNode([系统：复位、登录，从第一步重跑])
  replayNode -->|中断或复位失败| recoverNode["A8 重新核对条件，从头重跑"]
  recoverNode --> a25
  replayNode --> a21
  resultChoice -->|证据不足| queryNode["A3 补充取证，再经 08 试运行"]
  queryNode --> a21
  resultChoice -->|业务通过| a27["27 验证目标负载"]
  a27 --> a28["28 不确定目标时填写使用方式与等待要求"]
  a28 --> a29["29 确认目标、数据、判定及停止条件"]
  a29 --> a30["30 开始目标负载"]
  a30 --> loadNode([系统：同步检查业务和性能])
  loadNode -->|用户主动终止| a31["31 停止"]
  loadNode -->|目标结束或触发停止条件| settleNode([系统：停止派发，结算在途操作])
  a31 --> settleNode
  settleNode --> loadResult([通过、未达标、业务失败或无法验证])
  loadResult --> a21
  a21 --> a32["32 导出"]
  a32 --> a33["33 勾选报告、证据、验证包并导出所选"]
```

自动处理在真实产品中不应需要“显示结果”按钮。当前默认预览没有自动推进，26 后停在运行中；30 后的完成/结算同样只在检查模式手动演示，属 F1。工单提交业务通过后没有 27 的完整入口及绑定，属 F4。导出选择只是预览，不生成真实文件。

## 四、验证包复跑、跨项目复用及模板维护

```mermaid
flowchart TD
  packageEntry([已有验证包]) --> a34["34 加载验证包"]
  a34 --> a35["35 选择验证包文件"]
  a35 --> a36["36 检查并加载"]
  a36 --> packageChoice{完整性、路径、版本和资格有效吗}
  packageChoice -->|包损坏或不兼容| otherPackage["34 选择其他验证包"]
  packageChoice -->|模板停用| a37["37 选择有效版本并重新确认"]
  a37 --> packageChoice
  packageChoice -->|有效| a38["38 继续复跑"]
  a38 --> passwordNode["25 补密码并重新确认环境、数据和隔离"]
  passwordNode --> a39["39 开始复跑"]
  a39 --> runNode([系统：从头执行，关联原运行])
  runNode --> a21["21 查看本轮结果与模板资格"]
  projectEntry([验证另一个项目]) --> a40["40 切换项目"]
  a40 --> a41["41 选择项目"]
  a41 --> a42["42 确认新规则、字段语义、身份与查询并试运行"]
  a42 --> a43["43 查看复用结果"]
  a43 --> localResult([新项目结论由本项目证据得出])
  a21 --> a44["44 停用此版本，填写原因并确认"]
  a21 --> a45["45 生成修订候选"]
  a45 --> newCandidate([回到候选生成与重新验证，不直接发布])
```

F3：44 停用 v1.0 后，37—39 使用有效 v1.1，摘要显示已发布 v1.1，资格卡却显示 v1.1 已停用；40—43 又允许已停用 v1.0 被标为有效并得到迁移通过结果。停用状态没有按模板版本和入口统一处理。

F6：目前包内容、证据和迁移主要固定字段保持；保存结果、重复提交、权限隔离没有各自完整成果与迁移表达。不能将图中通用路径视为所有模板都已覆盖。

## 缺陷清单

| 编号 | 关联点击 | 本轮证据 | 建议优先级 |
| --- | --- | --- | --- |
| F1 | 02→03、26、30、39 | 默认模型检查、普通复跑停在处理中；完成和结算仅检查模式可模拟，默认不能自助点通整条链。 | 高：保留最终文案，同时给静态预览明确的模拟推进方式 |
| F2 | 04→05 | 修改目录及用途、勾选环境后调整发送范围，目录/用途恢复默认，环境确认丢失。 | 高：只撤销范围同意，保留无关输入 |
| F3 | 44→37→39→21；40—43 | v1.1 摘要“已发布”与资格卡“已停用”冲突；停用 v1.0 仍被新项目推荐/试运行。 | 高：按模板与版本核对资格，所有入口共用 |
| F4 | 27—30 | 工单提交的修复后通过结果无负载入口，负载仍固定编辑工单/字段保持。 | 中：绑定主流程和所选检查 |

| F6 | 22、32—43 | 种子检查的完整证据、包及跨项目映射主要未展开，当前仍是字段保持样例。 | 中：按对应业务展示成果与迁移 |

F1—F3 是本轮新增复现，F4—F6 为上一轮缺口的本轮再次核对。本轮不修复上述问题、不开发实际功能。截图布局未见明显遮挡或重叠；复跑准备页较长，确认及开始按钮需向下滚动。截图本身不能证明完整键盘、读屏或真实运行能力，未作此类验收结论。
