# 四页流程覆盖与文案精简

核对日期：2026-10-12。依据：需求 v0.41 的 R01—R52、候选设计 v1.7、最终计划 2.25。范围：静态界面、文案、入口和演示状态；不代表产品实现或真实执行验收。

## 结论

四页足以承载首版结构，字段保持的无模板主链可连续演示。**不能认定所有业务分支已完全覆盖**：种子流程的目标负载、其他模板的验证包/迁移，以及待定规则的观察记录仍有缺口。上一轮“未发现新阻断缺口”仅针对当时演示的字段保持主线，不是全部 R01—R52 的覆盖结论。

本轮已精简默认界面，并补充能在四页内表达的缺口状态。仍未开发实际功能。

## 仍开放的三处覆盖缺口

1. **工单提交的目标负载绑定**：修复复跑可保持所选种子检查，但该流程的报告没有完整目标负载入口；负载页和账本仍主要固定字段保持。不能把编辑工单的负载结论套给提交工单。
2. **非字段保持的成果和迁移**：工单提交结果页没有各检查完整复现证据；加载包和第二项目迁移主要是字段保持样例，尚未按保存结果、重复提交、权限隔离逐项表达对应规则、版本及范围。导出入口已齐全，不等于这些内容已齐全。
3. **待定规则的观察记录**：现有界面能保留待定、阻止参与对错判定，但尚无具体观察结果与同流程已确认检查并列的记录；“未执行”和“只观察未判定”应明确区分。

这些是预览覆盖缺口，不是要求开发新页面、评测平台或实际功能。现有四页可容纳后续补齐。本轮保留这些事项，不把未展示部分算作通过。

## 文案精简与小范围修正

- 默认界面删除“交互预览”“示例项目”“预览不会发送项目或凭据”、候选讲解副标题及重复提示。
- “填入示例密码/配置”“显示本轮结果”“显示结束示例”“完成示例结算”“切换示例”等演示控件只在 `?inspect=1` 检查模式显示；默认四页只呈现最终产品控件。检查模式的查询参数会随内部跳转保持。
- 文件加载改为最终应呈现的文件选择表单；示例包状态选择仅供检查模式使用。
- 保留发送范围、测试隔离、规则、计数、版本、独立审核、数据复位、停止结算、未知原因及结论限制。删除演示控件没有删除这些门槛。
- 未知报告改为“补齐最终取证并通过业务验证后再运行”，不再说“已证明业务错误”。历史文字不再一概称规则/映射相同。
- 工单提交修复复跑能显示所选两项检查的修复后结果，并保持主流程；报告导航能返回当前类型报告。均为预设状态转换，不证明真实缺陷已修复。

- 41 个来源于现有状态目录的页面做本轮 DOM 检查：有标题、无横向溢出、默认可见文字不含“预览/示例/演示”，且不含模拟控制按钮。该检查不是 41 条完整业务回归，也不是全部状态截图验收。

- JavaScript 语法检查通过；本轮所捕获浏览器 error 日志为空。截图与 URL/DOM 见 `screens.json`，状态检查见 `route-checks.json`，尺寸见 `layout-checks.json`。
- 原六个源文件已保存到 `before/` 并记录哈希；旧 QA 图片保留为历史，不作为本轮证据。
- 去掉演示文字是为了审阅最终文案。所有路径、账号、版本、结果仍是假数据；检查模式通过手动模拟状态推进。默认模式不会自行推进运行结果。文件选择不读取/验证包内容，导出不会生成文件；无网络、进程、真实模板发布、密码存储或负载操作。
